# 前端开发计划（V1.1）

最后更新：2026-04-15

## 1. 总体目标
在后端可交付基础上，完成可演示的前端闭环

## 2. 当前基线
1. 登录页已接入登录接口，角色分流已实现。
2. 注册页已接入注册接口并完成基础前端校验。
3. 路由守卫已建立（guestOnly / requiresAuth / requiresAdmin）。
4. 路由当前策略：`/post` 游客可访问，`/post/:id` 需登录，`/admin` 需管理员。
5. 其余页面仍以占位为主，未完成业务交互。

## 3. 任务拆分
## 阶段 A：账户闭环（优先级 P0）
1. 完成注册页表单与接口联调。（已完成）
2. 登录页补齐错误提示与加载状态。（进行中）
3. 完成路由守卫（未登录拦截、管理员拦截）。（已完成）
4. 完成退出登录入口。（未开始）

验收：
1. 普通用户登录进入 `/post`
2. 管理员登录进入 `/admin`
3. 刷新页面状态不丢失

## 阶段 B：内容闭环（优先级 P0）
1. 帖子主页：分页加载 + 瀑布流卡片。
2. 帖子详情：详情数据 + 评论列表。
3. 评论发布与删除（仅删除本人）。

验收：
1. `/post` 列表可见且可进入详情
2. `/post/:id` 可发表评论并刷新可见

## 阶段 C：个人中心与后台（优先级 P1）
1. 新增 `/profile`，接入 my / update。
2. 管理后台接入 `ping` + 至少一个治理分页 + 启停操作。

验收：
1. 普通用户无法访问后台操作
2. 管理员可执行启用/禁用并看到结果

## 阶段 D：样式收口（优先级 P1）
1. 登录/注册视觉统一。
2. 帖子瀑布流卡片样式统一。
3. 移动端宽度适配。

## 4. 交付清单
1. 可运行前端工程
2. 前端文档（本目录）
3. 关键页面截图（登录、帖子列表、详情评论、后台）
4. 联调问题与解决记录

## 5. 风险与应对
1. CORS 风险：统一通过 Vite 代理规避。
2. 字段名不一致风险：按接口逐个映射，不做全局猜测。
3. 进度风险：先做 P0，再做样式细节。

## 6. 明日任务（锁定）
1. 完成 `api/account.js` 的注册接口封装，页面不再直连 `request.post`。
2. 完成帖子主页 `/post`：接入 `/post/page`，产出第一版瀑布流。
3. 完成帖子详情 `/post/:id`：接入详情接口和评论列表接口。
4. 补一个统一顶部导航，提供“登录/注册/退出”入口。
