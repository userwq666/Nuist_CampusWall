## 3. 开发原则（本项目建议）
1. 先功能闭环，再视觉样式精修。
2. 每次只推进一个页面的“最小可用版本（MVP）”。
3. 每完成一个页面就做一次联调自测，不累计问题。
4. 页面不直接拼接接口 URL，统一走 `src/api/*`。
5. 不在页面层散落 `localStorage` 操作，尽量收敛到 store。

## 4. 页面与接口映射（用户端）
### 4.1 登录页 `/login`
1. `POST /api/account/login`
2. 入参：`{ username, password }`
3. 成功：保存 `token`、`userInfo`，按角色跳转  
   1. `ADMIN -> /admin`  
   2. `USER -> /post`

### 4.2 注册页 `/register`
1. `POST /api/account/register`
2. 入参：`{ username, password, nickname, educationEmail }`
3. 成功后跳转 `/login`

### 4.3 帖子主页 `/post`（瀑布流）
1. `GET /api/post/page?pageNum=1&pageSize=5`
2. 返回：`{ total, records }`
3. 页面能力：卡片流展示、翻页/加载更多、点击进详情。

### 4.4 帖子详情页 `/post/:id`
1. `GET /api/post/{id}`（帖子详情）
2. `GET /api/comment/page?postId=xx&pageNum=1&pageSize=5`（评论列表）
3. `POST /api/comment/create`（发评论）
4. `POST /api/comment/delete/{id}`（删自己的评论）

### 4.5 个人中心 `/profile`（建议新增）
1. `GET /api/account/my`
2. `POST /api/account/my/update`
3. 可选上传头像：`POST /api/file/upload?fileType=AVATAR`

## 5. 页面与接口映射（管理端）

1. 首次进入先调 `GET /api/admin/ping` 验证管理员权限。

### 5.2 后台核心模块

3. 评论治理：`/api/admin/comment/page`、`detail`、`enable/disable`

## 6. 关键接口口径与易错点
### 6.1 统一返回
```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

### 6.2 鉴权
1. 放行接口只有：
   1. `POST /api/account/register`
   2. `POST /api/account/login`
2. 其它 `/api/**` 默认都要 `Authorization: Bearer <token>`。

### 6.3 文件字段命名不一致（高频坑）
1. `POST /api/account/my/update` 使用 `fileID`（大写 ID）
2. `POST /api/post/create` 使用 `fileID`（大写 ID）
3. `POST /api/post/update/{id}` 使用 `fileId`（小写 d）
4. `POST /api/comment/create` 使用 `fileId`（小写 d）

### 6.4 枚举值口径
1. `targetType` 推荐传：`POST` / `COMMENT`
2. `fileType` 传：`POST` / `COMMENT` / `AVATAR`

### 6.5 跨域问题（开发环境）
前端开发建议配置 Vite 代理，避免浏览器 CORS 报错：
```js
// frontend/vite.config.js
export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true
      }
    }
  }
})
```
并将 `request.js` 的 `baseURL` 设为 `'/api'`。

## 10. 常见问题排查
### Q1：登录提示“请求失败，请稍后重试”
1. 先看浏览器 Network：是否 CORS、404、500。
2. 再看后端控制台：是否启动、是否端口 8080。
3. 再看 `request.js` 的 `baseURL` 与 Vite 代理是否一致。

### Q2：明明登录成功，访问接口仍 401
1. 检查 `Authorization` 头是否为 `Bearer <token>`。
2. 检查是否误调用了 `clearToken`。
3. 检查 token 是否过期（后端默认 7200 秒）。

### Q3：上传成功但图片不显示
1. 上传后返回的是 `fileId`，还需在业务接口中绑定。
2. 确认 `imageUrl` 来自后端返回，不要手拼本地路径。
3. 如果后端未配置静态资源映射，URL 可能 404。
