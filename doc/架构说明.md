# Nuist CampusWall 架构说明（V4.0）

## 1. 后端分层
1. `controller`：接收参数、返回结果。
2. `service`：业务编排、权限校验、状态流转。
3. `mapper`：MyBatis-Plus 数据访问。
4. `domain`：数据库实体映射。
5. `dto`：接口输入输出模型。
6. `common`：统一返回、异常、错误码、映射器。
7. `security`：JWT 与用户上下文。
8. `config`：MVC/分页/初始化/定时任务配置。

## 2. 前端分层
1. `src/api/`：接口封装层（request.js + 模块化 api），统一 Axios 实例。
2. `src/router/`：路由配置 + 守卫（guestOnly / requiresAuth / requiresAdmin）。
3. `src/stores/`：Pinia 状态管理（auth store，持久化到 localStorage）。
4. `src/components/`：公共组件（NavBar 等）。
5. `src/views/`：页面组件，按功能子目录分组（account / post / admin）。

重要约束：
1. 页面不直接调 Axios，统一走 `src/api/*`。
2. 页面不直接操作 localStorage，统一走 store。
3. 异步页面统一处理 loading / error / empty 状态。

## 3. 鉴权链路
1. `JwtAuthInterceptor` 拦截 `/api/**`。
2. 放行注册与登录。
3. 解析 token 后写入 `UserContext`。
4. 管理端通过 `AdminAuthService.adminCheck()` 做角色校验。
5. 前端路由守卫配合：未登录跳 `/login`，非管理员跳 `/post`。

## 4. 异常与响应链路
1. 业务层抛出 `BusinessException(code, message)`。
2. `GlobalExceptionHandler` 统一捕获异常。
3. `ErrorCodeToHttpStatus` 负责业务码映射 HTTP 状态。
4. 输出统一结构：`Result{code,message,data}`。
5. 前端 Axios 响应拦截统一处理错误提示。

## 5. 文件子系统
1. 上传目录：`temp/yyyy/MM/dd`。
2. 绑定迁移：`post/{id}`、`comment/{id}`、`avatar/{id}`。
3. 解绑回写 `TEMP`。
4. 定时清理超时 `TEMP` 为 `DELETED` 并删除物理文件。
5. 前端 Vite proxy：`/static/upload/**` -> `localhost:8080`。

## 6. 性能优化
1. 路由懒加载：每页独立 chunk（`() => import(...)`）。
2. 移除 Google Fonts 外链（国内被墙，消除 2 分钟首次渲染阻塞）。
3. Axios 超时 5s + ECONNREFUSED 友好提示。
4. ElementPlus 全局注册（单 bundle 优先于 dev 模式多请求）。

## 7. 架构结论
1. 当前架构满足课程项目可交付与可扩展要求。
2. 后续可平滑扩展消息通知、状态流转、审计日志等能力。
